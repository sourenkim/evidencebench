# Engineering Decision Log

## Use a deterministic baseline first

**Context:** Claim extraction and verification can be model-dependent, but the project must work without a paid API.

**Options:** Require an LLM; make a local model mandatory; provide deterministic implementations and provider protocols.

**Decision:** Provide deterministic claim segmentation, lexical retrieval, and lexical evaluation as the default.

**Reason:** It is reproducible, testable, private by default, and useful as a regression baseline.

**Trade-off:** Semantic paraphrases and nuanced contradictions are not reliably understood.

## Use dataclasses and standard-library serialization

**Context:** The data model is central and dependency count should remain low.

**Decision:** Use typed dataclasses and explicit `to_dict` conversion rather than making Pydantic a runtime requirement.

**Reason:** The schemas are small, explicit, and importable in minimal environments.

**Trade-off:** Runtime validation is implemented at input boundaries instead of being automatically generated by a schema library.

## Use protocols for providers

**Context:** Future implementations may use OpenAI, Anthropic, local models, or embeddings.

**Decision:** Define `LLMProvider` and `EmbeddingProvider` protocols without shipping provider SDKs.

**Reason:** The core remains provider-agnostic and no credentials are needed for tests.

**Trade-off:** Integrators write adapters and must define their own network/privacy behavior.

## Keep reports static

**Context:** Reports should be reviewable from a file and safe for untrusted source text.

**Decision:** Generate HTML with escaped text, inline CSS, and no JavaScript.

**Reason:** It works offline and reduces an unnecessary content-execution surface.

**Trade-off:** No interactive filtering in the initial release.
